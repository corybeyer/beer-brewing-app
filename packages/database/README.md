# Database

Owns PostgreSQL connections/schema readiness (`src/brewery_database/connection.py`) and versioned Alembic migrations (`migrations/`). It depends on database tooling, not FastAPI, UI, or deployment scripts. `brewery_database.recipes.PostgresRecipeDraftStore` implements the domain draft storage port with transactional create/load/replace and optimistic edit revisions.

Cluster-level role provisioning stays in `infrastructure/deployment/database/`; environment/credential parsing stays in `packages/config/`. The development migration `0002_recipe_drafts` adds six version-scoped draft plan tables. See [schema, permissions, transactions, and downgrade limits](../../docs/architecture/recipe-draft-storage.md). Production adopted this revision through PR #10 after reviewed rollout compatibility and verified backup checks. Future revisions require an explicit compatibility review. See the [backend foundation](../../docs/architecture/backend-foundation.md).

The development `0003_fermentable_catalogue` migration and `PostgresFermentableCatalog` add immutable sourced product revisions, ordered flavor descriptors, and grain-only composition links. Runtime catalogue grants are SELECT/INSERT only. Populated downgrade is refused; recipes are independent and retained. Review [catalogue storage and release requirements](../../docs/architecture/fermentable-catalogue.md) before deployment.
