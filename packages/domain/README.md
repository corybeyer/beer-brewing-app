# Brewing domain

Owns brewing business rules, states, and abstract ports. It must not import web/API frameworks, database drivers, UI packages, sensor protocols, or infrastructure.

`brewery_domain.recipe_plan` implements the first M2 structural recipe rules: version-local links, combined dependency/anchor cycle detection, and exact same-unit portion totals. See the [validation specification](../../docs/requirements/recipe-plan-validation.md) for its typed interface and limits. `brewery_domain.recipes` defines the draft storage protocol, metadata values, validation, and conflict exceptions. The database package supplies its PostgreSQL adapter. No publication transition or brewing endpoint is implemented yet.

`brewery_domain.extract_conversion` implements the first pure conversion core: explicit PPG/recovery/provenance at one comparison point, exact g/kg/oz/lb arithmetic, and immutable results retaining calculation version and assumptions. It supplies no default product catalogue, recipe mutation, HTTP endpoint, or flavor recommendation. See the [sourced conversion plan](../../docs/plan/extract-conversion.md#c1-domain-interface-and-current-evidence).

`brewery_domain.fermentable_catalogue` owns immutable sourced catalogue values, provenance/composition validation, and the append/load storage port. Unknown product yield stays absent; assumed values and complete grain bills require explicit provenance. It supplies no matching/recommendation algorithm. See [catalogue storage](../../docs/architecture/fermentable-catalogue.md).

`brewery_domain.conversion_proposals` captures immutable original/proposed drafts, full product snapshots, exact C1 evidence, and explicit yield/weighing overrides for one-to-one substitutions. Its revision guard detects stale review inputs; transactional retention/application remain unimplemented. See [proposal snapshot rules](../../docs/requirements/conversion-proposal-snapshots.md).

`brewery_domain.fermentable_matching` ranks a supplied complete extract composition before optional single-grain variations, preserving exact descriptor/color evidence and provenance-specific labels. Unknown composition and missing evidence stay explicit. `brewery_domain.blend_conversion` separately sizes selected grains from exact mass shares and explicit yield/recovery assumptions, retaining rational component masses/contributions under `grain-blend-gravity/v1`. Neither function reads remote data, mutates a recipe, or establishes mash readiness. Blend proposal/API integration remains future work. See [matching and sizing rules](../../docs/requirements/fermentable-matching.md).
